# 旧测距通道兼容：`orca.range.v1`

读取旧模型中已经存在、已经计算好的单值测距通道。**新厂商型号包应选择 [型号参考系测距 `orca.raycast.v1`](raycast.md)或[场景 site 测距 `orca.site_raycast.v1`](site_raycast.md)**：前者在契约中指定型号内的参考系，后者由场景为实例选择测量 site。

## 兼容场景的声明

下面是一项放进 `contract.json` 的 `inputs` 数组的请求；前提是旧模型绑定已经把已有测距通道映射为内部 `range` 对象。

```json
{
  "name": "proximity",
  "capability": "orca.range.v1",
  "object": "range"
}
```

它不会创建通道，也不是让厂商在新的 `model.xml` 中增加 `<sensor>`。新型号 XML 路径禁止原生传感器定义；上例仅用于已有旧模型的兼容绑定。

## 可填参数

| 参数 | 必填 | 默认值 | 含义 |
|---|---|---|---|
| `name` | 是 | — | 动态库输入成员名，本例为 `proximity` |
| `capability` | 是 | — | 固定填写 `orca.range.v1` |
| `object` | 是 | — | 已映射的旧测距通道名称，语义类型为 `range` |
| `dtype` | 否 | `f64` | 可省略；显式填写时必须为 `f64` |
| `shape` | 否 | `[]` | 可省略；显式填写时必须为 `[]` |

不支持 `direction`、`max_distance`、`exclude_self` 或 `fields`。方向、范围等行为来自原有通道，不由这项请求重新定义。

## 动态库收到什么

一个 `double`，即 `f64` / `float64`，shape 为 `[]`：

- 非负值：距离，单位 m。
- 有限负值：原通道的无命中标记，不是负距离。
- 非有限值：错误，不作为合法输入传入动态库。

负值原样保留，**不保证是 `-1`**；这与新 `orca.raycast.v1` 的固定 `-1` 约定不同。

## 关键限制

Orca 读取当前物理源样本中的既有通道结果，不另外发射射线。当前绑定要求该通道是单值原生 rangefinder；缺少通道或类型不符会在准备阶段报错。

普通新厂商接入无需使用本页。需要新增测距输入时，按上面两条路径选择参考系并声明对应的能力，无需增加原生测距通道。
